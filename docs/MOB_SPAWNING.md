# 自訂怪自然生成與診斷

2026-10-18，Paper 1.21.11／Java 21。這份文件說明目前實作及「看不到自訂怪」時的檢查方式；未取得使用者實服狀態前，不把某個條件當成已確認的實服故障原因。

## 先確認是否啟動

每次伺服器重啟後，管理員需要執行 `/finishrpg`。`config/mob_spawner.yml` 的 `enabled: true` 只代表允許啟用，不會自動啟動。原有設計仍保留，啟動紀錄及 `/mobspawn status` 現在會明確提醒。

預設 `mode: vanilla`：只接管原版自然生成的敵怪，在環境、時段及等級匹配後換成自訂模板。沒有原版自然敵怪事件，就沒有可替換的來源。白天明亮平地、只有創造／旁觀玩家、原版生怪關閉或數量已滿時，不會保證出現自訂怪。`/summon`、刷怪籠與其他插件的 CUSTOM 生成不屬於預設 NATURAL 來源。

主世界出生點預設有半徑 150 格的水平安全圈，地下也算安全區。請以生存／冒險模式在安全圈外、原版能生成敵怪的黑暗位置驗收。`/mobspawn spawn rotten_zombie NORMAL` 可以另外驗證模板生成；它仍檢查落點及本插件安全區，不代表自然替換已正常運作。

## 狀態如何判讀

執行 `/mobspawn status`，可見：

| 資訊 | 用途 |
| --- | --- |
| 配置啟用、RPG 已完成 | 區分 `enabled=false` 與尚未執行 `/finishrpg` |
| 玩家模式、世界、難度、安全區／保護區提示 | 辨識當前測試位置及玩家是否適合 |
| `spawn_mobs`（舊 `doMobSpawning`）、allowMonsters、monster-limit | 原版是否允許提供敵怪自然生成來源；上限 0 會提示 |
| 接管來源 | 預設 NATURAL；來源名稱會去空白並轉大寫，未知值記錄警告，CUSTOM／COMMAND 不接受 |
| 原版敵怪事件／被取消／替換成功 | 全服本次插件啟動後累計；取消事件只計數，不排程替換 |
| 自然替換最後結果、跳過統計 | 區分原怪狀態、世界／保護、數量／間距、Boss 區、時段／光照、玩家資格、落點、模板與生成被拒 |
| 腳下環境、時段與等級池 | 顯示普通模板 → 時段 → 環境 → 基礎等級的剩餘數量 |

腳下診斷只是參考，真正替換仍依原怪落點與該落點隨機等級篩選。全服最後結果也可能來自其他玩家或世界。

- 原版事件始終為 0：先看啟動狀態、生怪規則、亮度、玩家距離、原版數量上限及其他插件是否停用敵怪。不要只看「總嘗試」，它原本只在通過多個條件後才增加。
- 事件多、取消多：安全圈或其他插件可能在原版生成階段攔截，插件不會繞過取消。
- 有來源但沒有替換：查看跳過統計與最後結果；無匹配模板時會顯示哪個篩選階段歸零。
- 位置失敗：目前模板先檢查陸地兩格空氣與穩定地面，再檢查模型完整碰撞空間；水生、飛行或不適合的地形會保留原版怪，不會移到其他高度硬生成。
- 有替換成功：代表本插件已成功建立有效自訂怪並移除原怪；後續是否被其他插件清除、原版卸除或白天燃燒，仍需檢查實服。

已新增十種地形的 20 個普通怪及 10 個稀有 Boss，普通怪仍依實際環境與等級篩選，不跨區回退。BOSS、event-only 與熔核召喚物不進普通池；僅 wilderness-boss 標記的十個新 Boss 共用正常嘗試的 1% 稀有遭遇。完整內容與指令見 [MOB_ENCOUNTERS.md](MOB_ENCOUNTERS.md)。新安裝不排除 End，舊部署仍需從 disabled-worlds 移除實際 End 世界名稱。

## Debug 與補怪模式

`/mobspawn debug` 開啟後，約每 30 秒伺服器 tick 時間輸出一次全服累計摘要；即使沒有原版生成事件或尚未啟動，也會有摘要，避免「等待 30 秒卻完全沒日誌」。狀態指令不會自動更改世界規則、難度或保護設定。

若預期的是「玩家身邊定時出自訂怪」，可由管理員把已部署的 `plugins/CustomRPG/config/mob_spawner.yml` 設為：

```yaml
enabled: true
mode: supplemental
```

執行 `/mobspawn reload` 後，再執行 `/finishrpg` 啟動尚未啟動的系統。已啟動的狀態會在重載中保留。supplemental 依生怪週期嘗試生成，仍受玩家模式、安全區、難度、落點、模板、數量及間距限制；兩個模式互斥。

原版 1.21.11 的生怪規則名稱為 `minecraft:spawn_mobs`；診斷由 Paper GameRules.SPAWN_MOBS 讀取。若狀態顯示此規則關閉，管理員應確認原本關閉的用途後再決定設定；本插件不會替伺服器改規則。
