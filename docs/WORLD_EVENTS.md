# 世界隨機事件：臨時隕石島

更新：2026-10-24。目標 Paper API 1.21.11、Java 21。

## 目前玩法

隕石事件會在原世界的地形上方生成一座臨時實體島嶼。海面、山坡、樹木、礦石和建築不再作為怪物落腳地面，也不會被挖除。島嶼有平坦的黑石／玄武岩／凝灰岩地板、兩格高外牆及黑曜石核心，無須人工建場或資源包。

流程：持久隨機排程 → 選取已載入範圍 → 計算整個島嶼範圍的最高非空氣方塊 → 在其上方規劃島嶼 → 保存完整空氣／事件方塊快照 → 公告、隕石墜落 → 再檢查空間 → 分 tick 建造 → 生成 19 隻怪物 → ACTIVE → 全數有效擊殺 → 領取個人素材 → 返回玩家、清除實體和島嶼。

島嶼完成並進入 ACTIVE 後，使用 `/events join` 進場。施工中不可進場。討伐成功後仍可進場領獎，直到清理開始。

預設怪物：隕石寄生體 8、星界爬行者 4、殞落守衛 4、隕星精英 2、核心守護者 1。沿用既有 MobManager、等級、外觀與戰鬥系統，不另造傷害系統。等級取事件所在地區；模板在 `config/mobs/types/meteor.yml`，排除普通隨機生成池。

怪物出生高度固定為島面高度，避免最高方塊查詢選中核心、樹木、海底或原建築。每隻怪物依既有碰撞檢查嘗試不同位置。外部插件若取消全部生成，事件仍會報明確錯誤並清理；不會強制略過其他插件的取消。

## 玩家進出與清理

- `/events join [eventId]`：進入已開放的隕石島；省略 ID 時選取可用事件。
- `/events leave`：返回進場前的位置。
- 進場前先持久保存返回世界、座標與視角，儲存失敗不傳送；傳送遭取消則撤銷入場紀錄。
- 原返回位置無法站立或世界不可用時，依序尋找事件外緣或世界出生點。
- 清理前先送離仍在島嶼或其下方同一範圍內的參與者；傳送遭取消時暫停清理，保留地板。
- 透過 join 入場的離線玩家保留返回紀錄。若島嶼在離線期間結束，再登入時返回；重生後也會嘗試返回。
- 透過其他插件傳送離開事件範圍的玩家，不會在清理時被拉回島嶼。
- 事件保護與施工阻擋有高度範圍，原地面下方玩家不會因島嶼施工被移走或鎖住視角。島嶼的下底部到上方 32 格屬於事件空間。

## 設定與選址

設定：`plugins/CustomRPG/config/world_events.yml`，修改後重新啟動伺服器。既有設定缺少新節點時，程式會採用預設值，不必刪除設定。

```yaml
world-events:
  meteor:
    arena:
      radius: 12
      thickness: 3
      clearance: 6
```

`clearance` 表示原地形／建築最高方塊和島底之間保留的空間；島面還會加上地板厚度。缺少 `arena.radius` 時沿用舊 `crater.radius`，預設 12；厚度預設 3，間距預設 6。舊 `crater.max-depth` 不再決定新事件挖深，新事件沒有挖坑模式。

選址仍保留必要條件：主世界、非和平難度、已載入範圍、世界邊界、建築高度、保護區、事件重疊及存檔健康。高至世界建築上限而沒有島嶼空間的位置仍會拒絕，並重試其他位置。

每次搜尋最多嘗試 32 個候選點、每 tick 一個；只搜尋已載入區塊，不因選址生成新區塊。島嶼規劃內每一個將寫入的位置都必須為空氣；若空間在公告後改變，事件會取消，不會略過部分地板留下缺口。

一般事件保留 SafeZoneManager、自訂保護區、Boss 區及領地插件驗證。`/mmorpg event test meteor here` 額外略過本插件安全區；領地、邊界、高度、碰撞及存檔條件仍適用。`here` 使用玩家 X、Z，島嶼高度由整個範圍計算。

已支援 WorldGuard 7、標準 WorldEdit 7 及 FAWE 編輯保護 hook。其他已知領地插件缺少 adapter 時仍拒絕選址；`/mmorpg event info` 顯示整合狀態。一般事件要求已啟用的編輯工具 hook 正常；指定位置的管理員測試可略過編輯 hook，但不略過領地查詢。外部插件直接寫入世界仍可能造成衝突，不宣稱攔截所有修改。

## 資料與舊版本相容

```text
data/world-events/state.yml                 排程、事件、怪物、貢獻、素材、玩家返回位置
data/world-events/snapshots/<eventId>.yml   不可變 before/after 快照
data/world-events/natural-chunks.yml        保留的編輯來源追蹤資料
```

新事件保存 `generated-arena: true` 與 `arena-depth`。舊事件缺少標記時視為舊坑洞事件，升級後仍使用其原快照完成還原，不能刪除舊恢復資料。

新島嶼快照的 before 為原空氣 BlockData，after 為島嶼方塊；先原子保存快照和事件，再改世界。施工／還原每 tick 預設最多 128 個條目。清理只恢復仍與預期事件方塊相符的位置；遇到未知修改停止並保留快照，避免刪除外部新建方塊。

施工與事件期間保護破壞、放置、流體、活塞、爆炸、火焰、植物和傳送門等入口。保護範圍包含島嶼與外圍緩衝，不涵蓋島底以下的原地面。

停止、失敗、逾時都走 CLEANING。重新啟動後取消未結束戰鬥，先移除自己的怪物並清理島嶼，不補怪。chunk tickets 保留工作範圍，清理成功後儲存世界並釋放。停用插件不在單一 tick 強制還原全部方塊；恢復工作可在下次啟動繼續。

## 獎勵

沿用個人素材錢包與原有貢獻門檻：預設至少 1 點實際傷害及總貢獻 1%。符合資格的玩家獲得隕石碎片 12、星界水晶 3、隕石核心碎片 1，可於設定修改。右鍵核心或 `/events claim <eventId>` 領取，清理後仍可補領。錢包和領取紀錄原子保存，重啟不重發；沒有新增金幣或經驗獎勵。

事件怪物死亡必須有可歸屬的玩家戰鬥貢獻；無貢獻的必要怪物死亡仍使事件失敗。原版或插件產生的無來源傷害、技能召喚物歸屬及外部取消仍須實服驗收。
